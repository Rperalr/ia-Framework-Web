💡 PATRÓN: STRATEGY PATTERN + ROUTER PATTERN
═══════════════════════════════════════════════════════════════════════════════

El OrchestratorAgent implementa dos patrones de diseño:

1. STRATEGY PATTERN:
   Cada agente es una "estrategia" diferente de ejecución
   OrchestratorAgent elige la estrategia según el requestType

2. ROUTER PATTERN:
   OrchestratorAgent actúa como un "router" que dirige solicitudes
   a diferentes "handlers" basado en el tipo de solicitud

✅ BENEFICIO CLAVE: EXTENSIBILIDAD
═══════════════════════════════════════════════════════════════════════════════

¿Quieres agregar nueva funcionalidad?

TRADICIONAL:
  1. Modificar main()
  2. Escribir lógica directa
  3. Riesgo de romper existente
  4. Código acoplado

CON AGENTES:
  1. Crear nuevo agente que extienda Agent
  2. Implementar execute() y canHandle()
  3. Agregarlo a la lista de agentes
  4. ¡LISTO! (sin tocar código existente)

EJEMPLO:
┌──────────────────────────────────────────────────────────────────────────────┐
│ // 1. Crear nuevo agente                                                    │
│ public class SlackNotificationAgent implements Agent {                       │
│                                                                              │
│   @Override                                                                 │
│   public CompletableFuture<Map<String, Object>> execute(UserRequest req) {  │
│     // Enviar notificación a Slack                                          │
│   }                                                                         │
│                                                                              │
│   @Override                                                                 │
│   public boolean canHandle(UserRequest request) {                           │
│     return "slack".equalsIgnoreCase(request.getRequestType());             │
│   }                                                                         │
│ }                                                                           │
│                                                                              │
│ // 2. Agregarlo al orquestrador                                             │
│ agents.add(new SlackNotificationAgent());                                   │
│                                                                              │
│ // 3. ¡YA FUNCIONA!                                                         │
│ UserRequest slackReq = new UserRequest();                                   │
│ slackReq.setRequestType("slack");                                           │
│ orchestrator.processRequest(slackReq);  // ← Automáticamente lo usa        │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘

🔑 RESUMEN: CÓMO FUNCIONA LA ORQUESTACIÓN
═══════════════════════════════════════════════════════════════════════════════

1. Usuario envía UserRequest con requestType
2. OrchestratorAgent recibe solicitud
3. OrchestratorAgent analiza: request.getRequestType()
4. OrchestratorAgent busca: ¿Quién puede manejar este tipo?
5. Cada agente responde canHandle(): true/false
6. OrchestratorAgent selecciona el agente que retornó TRUE
7. OrchestratorAgent ejecuta: agent.execute(request)
8. El agente hace su trabajo especializado
9. Agente retorna resultado
10. OrchestratorAgent consolida resultado
11. Usuario recibe respuesta
